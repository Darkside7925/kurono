# E1000

`src/drivers/e1000.cpp` and `e1000.h`. Intel E1000 gigabit Ethernet.

## Why this NIC first

The E1000 and E1000e are the most widely emulated NICs around. QEMU, VirtualBox and
VMware all offer one, and real Intel gigabit adapters use the same register map. So it's
the practical first target, and it works on metal and in a VM.

## What it does

1. finds the device on the PCI bus at boot (vendor 0x8086, several device IDs)
2. maps the MMIO BAR into kernel space
3. sets up the transmit and receive descriptor rings
4. reads the MAC address out of the card's EEPROM
5. enables RX and TX
6. `SendPacket(buf, len)` for outgoing frames
7. the main loop polls for received frames

## Polling, not interrupts

RX is polled from the main loop. Simpler, and it skips IRQ allocation entirely. The cost
is latency bounded by frame rate instead of hardware timing, which is fine at this stage.

## Into the stack

Raw Ethernet frames go up to `network.cpp`, which hands them to `tcpip.cpp`.

## When it breaks

| Symptom | Cause |
| --- | --- |
| driver not found at boot | the PCI scan didn't see an 0x8086 E1000 |
| no packets received | RX ring not set up, or the descriptor count is wrong |
| transmits fail | TX ring full, or TCTL not enabled |
| wrong MAC | EEPROM read path, check the EERD register |

## Files

- `src/net/network.cpp` takes frames off this
- `src/kernel/kurono_kernel.cpp` polls `e1000.Poll()` in the main loop
