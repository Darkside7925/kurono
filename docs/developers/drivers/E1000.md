# E1000 Network Driver

`src/drivers/e1000.cpp` and `e1000.h` implement the Intel E1000 Gigabit Ethernet driver.

## 1. Why E1000

The Intel E1000 (and its derivative E1000e) is the most widely emulated NIC in virtual machines. QEMU, VirtualBox, and VMware all support it as a virtual network device. Real Intel GbE adapters use the same register map. This makes the E1000 a practical first NIC target that works on both real and virtual hardware.

## 2. What it does

The driver:

1. Detects the E1000 on the PCI bus at boot (vendor 0x8086, various device IDs).
2. Maps the MMIO bar into the kernel address space.
3. Initializes transmit and receive descriptor rings.
4. Sets the MAC address from the card's EEPROM.
5. Enables RX and TX.
6. Provides `SendPacket(buf, len)` for outgoing frames.
7. Polls for received frames in the main loop (no RX interrupt used in current implementation).

## 3. Polling model

The current driver polls for received packets in the main loop rather than using interrupts. This is simpler and avoids IRQ allocation complexity. The trade-off is that latency is bounded by the frame rate rather than by hardware timing. For an OS at this stage that trade-off is acceptable.

## 4. Integration with the network stack

The E1000 driver hands raw Ethernet frames up to the `network.cpp` layer which passes them to `tcpip.cpp` for processing.

## 5. Common problems

| Problem | Likely cause |
| --- | --- |
| Driver not found at boot | PCI scan not detecting 0x8086 E1000 device |
| No packets received | RX ring not initialized or descriptor count wrong |
| Transmits fail | TX ring full or TCTL not enabled |
| MAC address wrong | EEPROM read path failing; check EERD register |
